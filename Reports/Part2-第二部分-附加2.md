# Part2 第二部分 附加2：我还是目标函数的端水高手

## 1. 为什么存在这么多损失函数

损失函数不是个技术细节，它是「我想要模型输出什么样的东西」这句话的公式化。人说不清「看着像」，只能找一个能算的替身，不同的替身各自偏一边。

```text
L1      |x - y|              逼输出学条件中位数，对离群值不敏感，结果比 L2 锐
L2      (x - y)^2            逼输出学条件均值，对大误差惩罚更狠，结果更糊
感知损失  VGG 特征图的 L1      不比像素，比结构；允许像素错位
对抗损失  判别器判真伪        不定义距离，只要求「像真的」
对比损失  正样本近、负样本远   比相对关系
```

L1 和 L2 的差别本身就说明了问题：它们都在说「输出要接近真值」，但对「接近」的定义不同。L2 把误差平方，一个大误差的权重会被放大很多，所以模型宁可输出一个处处都对一点的模糊结果，也不敢冒险做尖锐的判断。L1 对大误差惩罚线性，更愿意赌一把锐利的结果，代价是可能赌错。

感知损失往前一步，不再问「像素差多少」，而问「VGG 中间层觉得这两张图像不像」。它允许输出和真值在空间上错开一点，只要结构对。这在超分、去噪这类「答案不唯一」的任务上是必须的 —— 一张 4 倍放大的图有无数种合理答案，逐像素比只会逼模型输出所有答案的平均值，也就是糊。

所以多的根源是：任务不同、失败模式不同、允许的不确定性不同。没有一个损失能同时占尽所有好处，因为它们的偏置方向是矛盾的 —— 逐像素损失偏向「平均」，感知和对抗损失偏向「锐利」，一个要稳一个要险。

## 2. 全部用上会有什么问题

有四个层面的问题，前两个是本质的。

**第一，目标本身互相冲突。**L1 的最优解是条件中位数，感知损失的最优解是一个能骗过 VGG 的解，两个解通常不是同一个点。同时优化等于在求一个可能不存在的共同最优点，最后落在某个折中位置，每一项都不是最优。

**第二，尺度不一致，权重名义上存在、实际上不存在。**各项损失的数值量级天然差很多：

```text
像素 L1        0.01 ~ 0.02 量级
感知损失        0.05 ~ 0.5  量级（取决于层深和归一化）
对比损失        原始值 1e-4 量级，乘 λ=0.05 后 1e-5 量级（任务三实测）
```

如果直接把几项相加，谁数值大谁主导梯度，`λ` 设成多少都救不了。我在任务三里就实测到这一点：对比损失乘完 `λ=0.05` 之后是 2e-5，而同一时刻像素损失是 1.7e-2，差了近三个数量级，那一项实际上等于没有参与训练。这是「全部用上」最隐蔽的失效方式 —— 不报错、不崩、看着在训，但其实只有一项在起作用。

**第三，计算成本。**每多一项损失就要多一次前向：感知损失和对比损失都要过 VGG，对抗损失还要多一个判别器的前向和反向。任务一里实测，加上感知损失后每个 epoch 从 31 秒变成 38 秒，涨了 23%，而这还只是多了一个 VGG 前向。

**第四，超参空间爆炸。**n 项损失就是 n 个权重，而且它们互相耦合 —— 调大了感知项，像素项相对就变小了，两组超参之间不是独立可调的。

## 3. 为什么「功能各不相同的损失叠在一起反而更差」

我自己的实验就是这个问题的实例。任务一里 A、B 两组只差一个感知损失开关：

```text
B  纯 L1              PSNR 32.9006  SSIM 0.9374  LPIPS 0.0340
A  L1 + 0.1 感知损失    PSNR 31.2338  SSIM 0.9151  LPIPS 0.0428
```

三项指标纯 L1 全赢。感知损失不是坏东西，它是被放在了一个不匹配的任务上：Rain200L 是合成的，`有雨 = 无雨 + 雨层` 精确成立，真值唯一，像素损失就是和任务匹配的指标；而感知损失的长处恰恰是「允许输出偏离真值」。

再深一层的原因在于梯度方向。两项梯度的余弦如果为负，合成的更新方向对其中每一项都不再是下降方向；负得越多，互相抵消越严重，最坏情况下两项几乎抵消、总步长接近零。表现出来就是训练震荡、收敛变慢、最后停在一个谁都不满意的位置。

还有一种相反的情况：任务三里，对比损失加进去之后指标几乎没变（PSNR 从纯 L1 的 32.9006 / 33.2291，变成加了对比损失的 33.1373，正好落在两者中间）。这不是「打架」，而是它根本没参与 —— 它的梯度量级太小，被像素损失完全盖住了。所以「叠加损失变差」和「叠加损失没反应」其实是同一个病的两个症状：名义权重和实际贡献脱节。

## 4. 怎么保证各项的作用只由超参数决定

问题的定义很清楚：要让

```text
某一项对参数更新的实际影响力  ∝  我给它设的 λ
```

而现在实际影响力正比于 `λ × 该项梯度的范数`，梯度范数由损失本身的量级决定，这正是要消掉的那个因子。

我的方案分两层：先把每一项的梯度归一化到同一尺度，再让权重自适应。

**第一层，梯度范数归一化。**

```text
对每一项 i：
    g_i = ∇_θ L_i                     只在共享参数 θ 上求
    s_i = EMA(||g_i||_2)              指数滑动平均，跨 step 平滑
    L_i' = L_i / (s_i + ε)            用梯度范数而不是损失值做除数

总损失 = Σ λ_i · L_i'
```

除的是梯度范数而不是损失数值，这一点是关键区别。损失值的大小和梯度大小不是一回事 —— 一个数值很小的损失可能梯度很大（曲线陡），一个数值大的损失可能梯度平缓。真正决定更新方向的是梯度，所以要归一化的是梯度。

用 EMA 而不是当步的 `||g_i||`，是为了避免这个除数本身被单个 batch 的噪声带偏，导致训练不稳定。

**第二层，让权重自己学（不确定性加权）。**

```text
每个损失项 i 配一个可学习的 log σ_i：

    L = Σ [ L_i' / (2·σ_i²) + log σ_i ]

σ_i 大 → 这一项噪声大、不可信 → 自动降权
log σ_i 项防止 σ_i 无脑变大逃避学习
```

这个写法的来源是 Kendall 等人的多任务不确定性加权：把每个任务的输出看作一个带高斯噪声的观测，`σ_i` 就是那个噪声的标准差。优化的结果会自动把权重分配给「当前学得好、梯度干净」的那些项。

两层结合之后，`λ_i` 的含义就干净了：它表示我主观上希望这一项占多大比重，剩下的部分交给数据和梯度自己去平衡，不再受各项损失本身量级的污染。

补充一个更简单但代价更高的做法，作为对照：如果两项梯度夹角为负，就把其中一项投影到另一项的正交补空间上再相加，强行保证不会互相抵消。这个办法直接解决了冲突问题，但每次更新都要多算一次内积和投影，而且无法处理三项以上的情况，我没选它。
