# Part2 第二部分 附加3：来看看标准的对比学习

## 1. 开头那句话有道理吗，对比学习一般有哪些特征

有道理，但要把「像」和「是」分开。

上一题里那个变体和标准对比学习确实共享了两个核心件：一个编码器把样本映射到特征空间，以及用相似度（这里选了余弦）衡量两个特征的关系。这两点是对比学习的骨架。

但骨架之外的东西几乎都不一样，差别集中在四处。

```text
                      标准对比学习              感知损失的对比变体
样本从哪来             数据增强，自监督          数据集直接给，有监督
正负样本              同一张图的两个视图        无雨图 / 有雨图
负样本数量            成百上千（batch 或队列）  只有 1 个
损失形式              InfoNCE + softmax + 温度  两项直接相加
被优化的对象          编码器本身                编码器冻结，优化的是 UNet
训练完之后            编码器拿去下游任务用       这套损失就是终点
```

最后一行是最本质的区别。标准对比学习是表示学习，目标是练出一个好编码器，练完之后把编码器摘下来给下游用；而这个变体里编码器是冻结不动的，它是把编码器当成一把固定的尺子，用它的输出去监督下游的 UNet。方向是反的：一个是在造尺子，一个是在用尺子。

所以题干开头那句「不太一样」说得对，但更准确的说法是「借用了对比学习的形式，但目的不同」。

对比学习一般具有这些特征：

**第一，自监督。**不需要人工标注，正样本是自己构造的 —— 同一张图做两次不同的数据增强（裁剪、颜色抖动、翻转），得到两个视图，它们互为正样本。这就把「无限多的无标签数据」变成了监督信号。

**第二，在特征空间里做拉近和推远。**不比较像素，比较编码器输出。一旦编码器变了，这个空间就跟着变，所以它天然和编码器训练绑定在一起。

**第三，依赖大量负样本。**SimCLR 靠超大 batch，MoCo 靠一个动量队列维护历史负样本。负样本越多，模型越难靠「让所有样本都挤在一起」来偷懒，学到的表示判别力越强。

**第四，用 InfoNCE 损失。**一个正样本加 N 个负样本，通过 softmax 归一化，本质是一个 N+1 分类问题：从 N+1 个候选里把正样本挑出来。温度系数控制分布的锐度。

**第五，学到的是实例级判别能力。**目标是让模型能区分「这是哪一张图」，这个能力迁移到分类、检测、分割上通常都有效。

## 2. 用对比学习的语言解释这个变体：什么是正样本，什么是负样本

先把三个角色对上：

```text
锚点 anchor    模型输出 derained    要去对齐的那个东西
正样本         无雨真值 clean       希望锚点靠近它
负样本         有雨输入 rainy       希望锚点远离它
```

所以对编码器来说，正样本是无雨真值图，负样本是有雨输入图。

这里有个反直觉的地方，值得单独说。标准对比学习里，锚点和正样本来自同一个实例的两个视图，是「同一件事的两种看法」；而这个变体里，锚点是模型的预测，正样本是目标真值，两者来自不同来源，地位不对等。严格按定义，它更接近 triplet loss 或者 ranking loss —— 三元组 (锚点, 正, 负) 拉近推远，而不是 InfoNCE 那套「从一堆候选里挑一个」的机制。少了 softmax 归一化，也就少了「负样本越多越好」那个性质。

还有一个更要紧的问题：这里的负样本不够负。

任务三里我实测过，在 Rain200L 上

```text
cos(无雨, 有雨) = 0.9675
```

也就是说负样本和正样本自己就有 96.75% 像。对比学习之所以有效，前提是负样本足够「不像」，需要模型费力气才能把它们推开，这个推力才携带信息。而这里正负样本本来就几乎重合，可推开的余量只有 0.03 左右，模型几乎不用学就能满足这一项。

这也解释了为什么整项损失的量级小到 1e-4。它的问题不在实现，在数据：合成雨对全局特征扰动太小，对比学习赖以起作用的「负样本远离」这个前提在这里不成立。

## 3. 三选一之第二项：设计一个算法，微调出更好的编码器

### 3.1 为什么需要微调编码器

现成的 VGG19 是在 ImageNet 上训的，任务是分类，它学到的东西是「这张图里有没有狗、有没有车」。雨丝对分类几乎没有影响 —— 一张图有没有雨，仍然能正确分出是猫还是狗，所以 ImageNet 的训练信号从来没有逼它去关注雨纹。

任务二里已经观察到另一个问题：截到前 35 层，128×128 的输入走到那里只剩 8×8，一个特征点管 64 个像素的格子，它回答的是「这一片里有没有某类结构」，而雨丝是又细又长的高频纹理，在这个尺度上基本消失了。

两件事叠在一起，结论是：这个编码器对雨纹不敏感，用它算出来的感知损失和对比损失，判别力都有限。

### 3.2 算法设计

整体思路：不改变「输入图像 → 特征向量」这个结构，只换掉产生特征的方式 —— 在雨纹数据上重新训一个编码器，让它被迫学会表征雨。

分三步。

第一步，构造代理任务。

Rain200L 天然提供了配对数据，`有雨 = 无雨 + 雨层` 精确成立，所以雨层的真值可以直接算出来：

```text
雨层 R = rainy − clean
```

R 是一个稀疏的、以细长条纹为主的残差图。把「预测雨层」作为代理任务，输入 `rainy`，编码器输出特征，接一个轻量解码头还原出 R。编码器要能把雨层还原出来，就必须在中间层保留雨丝的位置和形态信息。

这比直接拿「去雨」当代理任务更好，因为去雨要求的是重建整张图，模型容易走捷径 —— 大部分区域直接复制输入就行，雨丝那百分之几的像素对总损失贡献很小。而预测雨层等于只盯着那百分之几，信号不会被淹没。

第二步，训练。

```text
编码器      VGG19 前 35 层（或更浅的 relu2_2 / relu3_3，因为雨丝是高频结构）
解码头      四层上采样卷积（8→16→32→64→128），输出单通道
损失        R 的 L1（雨层有正有负，用 L1 比 L2 更稳）
数据        Rain200L 训练集 1800 对，随机裁剪 128×128 + 水平翻转
优化器      Adam，lr 1e-4，冻结前 1/3 的浅层，只微调中后层
轮数        20 轮
```

冻结浅层是因为浅层学的是边缘、方向这类通用特征，对所有图像任务都有效，没必要改；真正需要适应的是中后层，它们负责把边缘组合成「结构」，而雨纹恰恰在这些层还没有被组合成可识别的东西。

第三步，评估与回接。

评估分两级。

```text
直接指标    雨层预测的 IoU / F1，看编码器是不是真的学会了找雨
间接指标    把微调后的编码器装回 EasyContrastiveLoss，
            重新训 UNet，看 PSNR / SSIM / LPIPS 有没有变化
```

另外有一个专门针对我们已发现问题的检查：微调之后，`cos(无雨, 有雨)` 应该会下降。如果新编码器真的更关注雨纹，它对两张图的区分度就会变大，对比损失的可优化区间从 0.03 扩大，那一项的梯度量级也应该从 1e-4 往上走。如果这个数没变，说明微调没起作用，这是一条比 PSNR 更灵敏的检验。

### 3.3 可能的问题

最大的风险是过拟合到 Rain200L 的特定雨纹。这个数据集是把一组有限的雨层随机叠加到不同背景上生成的，雨纹本身种类不多。如果编码器记住的是这几十种雨层的样子，换到真实雨天就未必管用。

所以评估时要按雨层分组留出验证集 —— 用没见过的雨层去测，而不是随机划分。这一步不做，测出来的提升可能是假的。

第二个风险是编码器和下游任务脱耦。微调后的编码器擅长提取雨纹，但 UNet 需要的可能还包括背景结构的信息。如果微调过度，编码器变成一个只会看雨、不理其他东西的专家，感知损失反而会退化。所以上面设计里只微调中后层、且学习率设得很小，是为了在「适应新任务」和「保持通用性」之间留一个缓冲。

### 3.4 预期

按现在掌握的证据，我的预期是间接指标提升有限，但那个诊断量（正负样本相似度的差）会明显变化。原因是任务三已经证明这个损失在这套数据上失效的根源是「负样本不够负」而不是「编码器不够好」—— 雨层本身对全局特征的扰动就小，换个编码器能改善的幅度是有上限的。

如果真要做，更值得尝试的方向可能是改池化方式：现在 `AdaptiveAvgPool2d(1)` 把空间信息全丢了，而雨丝恰恰是空间局部的。改成保留一部分空间维度的池化（比如分成 4×4 区域分别平均，得到 512×16 的特征图，展平后是 8192 维），比换编码器更直接对症。
